# Decision model

`native/model/` reads what code knows about values, once, from types and syntax. Typed rules are queries over it. Code knows **facts**: a test establishes one, it holds for a while, and code uses it. The rules find facts that are lost and rebuilt, established twice, established outside their owner, or spread across files.

## Glossary

- **Value**: data reached from a root (a variable, `this`, or an expression evaluated once) through property reads and literal-key element reads. Identity comes from symbols, not text; two calls written alike are different values. A variable that only names data is that data: after `const { kind } = item`, `kind` is `item.kind`.
- **Field**: the property declarations a value ends at. Two values are the same field when they share a name and a declaration.
- **Form**: a structural comparison key for an expression relative to a value: the value becomes `$`, literals compare by value, and external references by resolved symbol. The **syntactic form**, for shared indexes built without a checker, has a root node become `$` and other identifiers compare by name; it can miss a value reached through another variable naming it.
- **Vocabulary**: the finite literal values of a declared type, at least two string or number literals once `null` and `undefined` are removed.
- **Claim**: what a test establishes: the value is one of a set, within its vocabulary or among present, `undefined`, `null` and other falsy values. Claims compare as sets: same, opposite, or implies.
- **Test**: a place where code learns a claim: a literal comparison, `includes` or `has` on a collection of known values (a literal list, a literal tuple type, or a `new Set` of a literal list, directly or as a `const` initializer, read as declared), or a presence test (a truthiness test or a comparison with `null`/`undefined`).
- **Rejection**: a place that rejects input without the model reading its claim: a `throw` under conditions reading input, including that of an earlier `if` in the same statement list that returns early on one side, or a call to a function that makes one. Narrowing-only tests are not rejections: they establish only what TypeScript's narrowed type keeps (presence, `typeof`, `instanceof`, `in`, type guards), including through a const boolean local, and a truthiness test beside a test requiring the same value to be an object. In rule messages this is a "check".
- **Guard** and **entry test**: a guard is a test after which code works only where the claim holds and otherwise leaves without using the value. An entry test is a function's guard on a parameter before its work; its **fallback** is the constant it leaves with.
- **Leaves**: cannot reach its end, by its ending: it returns, throws, breaks, continues or calls a function returning `never` on every way through it.
- **Callers**: the calls to a function across the program's project files, known only for a named function that compares a parameter with a string literal or declares a string result. A call to a member of a type the function's class instances are assignable to, such as an interface, counts as a call to the method. They are complete when the function is used only by being called: not passed, stored, default-exported, renamed on import or export, destructured or overloaded, and not a member a base class also declares. Calls on `any`, through element access and from outside the program are not seen.
- **Boundary**: where a value passes between functions: an argument to a parameter, a call's result, a store into a class's state, or a **gate** (a selector and handler in one object or class taking the same first parameter type). The questions there are what is known on the way in, whether the receiving type keeps it, and whether the receiver rejects it again.
- **Flow**: what a function does with its input: the data each value is built from, the rejections it makes, the calls it passes data to, and what it returns. A call is **discarded** when nothing receives its result: awaited or not, it is a whole expression statement.
- **Owner**: who a type belongs to: its class, a runtime value merged with it, or its declaring module or namespace. Importing a type does not transfer ownership. A property's owner is the named class, interface or type alias declaring it; code inside it is, for a class property, code of a class that has the property, otherwise code inside that owner. Ambient declarations and types in script files have no owner.
- **Predicate**: a parameterless member whose whole body is a field test of `this`. A **helper predicate** is an exported one-parameter function doing the same for its parameter. A **selector** is a function whose result is a boolean of tests on its parameters, or a type predicate.
- **Outcome**: what an arm produces: whether it runs **commands**, and what its result depends on: none, empty, constant, the value, parts of it, other data, or a mix. A constant result without commands is a **lookup**.
- **Optional settings**: for a function with one project object result type whose every return is an object literal or another value of one object type assignable to it, whether each returned object sets each optional property (marked `?` or typed with `undefined`): set, left out (missing or `undefined`), or maybe set (a value that may be `undefined`, or a spread that may carry it). A value other than a literal is read by its type: a required property is set, an optional one maybe set, a missing one left out.
- **Write**: a place where code changes data: an **assignment** (with `=`, each target of a destructuring assignment, or the variable of a for-in or for-of loop that does not declare it), an **update** (a compound assignment, `++` or `--`), or a **mutation**, a method called on a value. Assignments and updates **rebind** their target. A mutation is not known to change anything; each reader decides whether to count it.
- **Ending**: how a statement can end: by reaching its end, by a `break` leaving a statement around it, by a `continue` resuming a loop around it, by a `return`, or by a `throw` or a call returning `never`, each with the writes made on the way and the definitions reaching it. A loop ends when its condition fails or through a `break`; one without a condition, or whose condition is `true`, only through a `break`. A `switch` reaches its end when no case matches unless it has a `default` or covers every value. A `throw` in a `try` block goes to its `catch` clause, and a `finally` block runs on every way out. Without a checker, as for the shared index, no call is known to return `never` and no `switch` to cover every value.
- **Left values**: for an `if` or `switch` statement or a conditional expression run as a statement, the data its branches rebind on ways that reach its end and the statements after it read before every way rebinds it again, and the data they rebind before a `break` that the statements after the left statement read. Data counts when its root is a variable or parameter of the function declared outside the decision, or `this`; writes into one root are one entry. Writes in callbacks, in loops inside the decision, and mutations are not read. Nothing is left to statements starting with a `return`.
- **Definition**: what gives a place (a variable or `this`, then a property path) its value where code reaches a point: an assignment, update or destructuring that rebinds it, the declaration initializing its variable, or the value it held **before** the code being read. Each way out of a statement carries the definitions reaching it per place: a rebinding replaces the earlier ones, unless it may not run (in a branch of a conditional expression or on the right of `&&`, `||` or `??`); ways that join keep the definitions of both; a loop's ways also keep those of earlier iterations, and a `catch` those of any part of its `try` block.
- **Merge**: where the ways through a decision (an `if` or `switch` statement, or a conditional expression run as a statement) that reach its end rejoin. Each **arm** is one way in: the `then` or `else` branch, the `case` clause a way enters (falling through later clauses to the end or a `break` leaving the `switch`), a branch of the conditional expression, or the way no branch takes, when there is no `else` or the `switch` has no `default` and does not cover every value. An arm **finds a value missing** when the checker's narrowing says it is `undefined` or `null` there: for an arm entered by a condition, the type the value holds before the decision, read as its constraint when generic and with `undefined` and `null` added, narrowed by that condition alone, so an entry of a record whose type omits `undefined` is missing in `if (!entry)`; for a `case` clause, the type the checker narrows where it starts. Any test the checker narrows by counts: truthiness, comparisons with values typed `undefined` or `null`, `typeof`, `instanceof`, type guards and discriminants. A **phi** is a value at the merge: the definitions reaching it along each arm. It is **carried** when its value outlives the pass: data of `this`, or a variable declared outside the innermost loop around the decision; its arms then change state rather than choose what this pass works on. The value held before is read through the statements before the decision in each statement list around it, back to the declaration of its variable, but not past a loop or the start of the function.
- **Provenance**: the kinds of value an expression gives: **existing** data (a variable, parameter, property, element, `this`, or an entry a global collection's `get`, `at`, `find` or `findLast` returns), a **fresh** object (an object or array literal, `new`, a function, class or regular expression), a **constant** (an expression whose type is a single value: a literal, an enum member, `null`, `undefined`, a unique symbol), the **size** of a global collection or a string (`length`, `size`), or a **computed** value (any other operator, or a call not followed). Freshness is read from the expression, since no type states it. A `const` gives what its initializer gives, another variable or a parameter what its definitions reaching the read give; a call to a project function, or a read through a project getter, gives what its returns give, a parameter giving what the call's argument gives, and reaching the end of the body gives `undefined`; a generator, or an async function not awaited, gives a new object; a global collection method building a new array (`map`, `filter`, `slice`, `concat`, …) gives a new object; a call back into a function being followed is computed; a conditional expression and `&&`, `||`, `??` give what either side gives. Provenance is read where the value is used: a new object the code before that point makes reachable from data that outlives it (an effect that may carry it into `this` or into data of a variable declared outside the code read) is existing data there, and so is the size of a collection read before an element is appended to it, which then names that element. A collection member is one every declaration of which belongs to a global type (`Array`, `ReadonlyArray`, `String`, `Map`, `ReadonlyMap`, `WeakMap`, `Set`, `ReadonlySet`, `WeakSet`), resolved in the global scope and compared by declaration, so a subclass inherits it and a project type of the same name is not one; on a union receiver, every member's type must agree on what it does.
- **Effect**: what a write does to the object it acts on (its **receiver**): **store** a value under a key (`Map.set`, `WeakMap.set`, an element assignment with a computed key), **append** one (`push`, `unshift`, `Set.add`), **remove** entries (`delete`, `clear`, `pop`, `shift`, `splice`), or **change** it otherwise (an array reordered or filled, an assignment or update of data inside it, or a method whose body is unknown run as a command). An effect also names the expressions whose data it may put into its receiver: the stored value, or every argument of a method whose body is unknown. Rebinding a variable is a definition, not an effect. A call or construction resolving to a project function with a body makes the effects of its **summary**: the effects its body makes, including through the calls it makes, on its receiver (`this`) and its parameters (the summary also lists what it reads of them, see Read), each with a property path and the parameters whose data it may carry, mapped at the call onto what the call is made on (`this` for `super`) and its arguments up to the first spread. Effects on the function's own locals, on module state, on a parameter it rebinds, and a construction's effects on the new object are not in it; a function reached again while it is summarized gives nothing on that call. Otherwise a call acts on its receiver only when every declaration of its callee is a method: a function held by a property or exported by a namespace, a callee the checker cannot resolve, and a default-library method outside the collection effects above have none.
- **Origin**: where a value comes from when the model cannot follow it further: a new object, a constant, a size read, a read of data, a computed value, or a parameter or variable whose definitions are not seen. Origins are followed like provenance, through `const` initializers, the definitions of other variables reaching the read, conditional and logical operators, and calls to project functions (a parameter giving the origins of the call's argument), and through the entries of local containers: a lookup gives the origins of the values stored, and a `for-of` loop binds its keys and values to theirs. Unlike provenance, origins keep identity: two keys from different size reads are different origins.
- **Contents**: what a local container holds: a variable of its function, never rebound, created empty (an empty array literal, or a global collection constructed without arguments) and used only as a container (the receiver of collection methods, by element access, for its size, or iterated by `for-of`). Every effect in the function storing or appending into it is an **entry**, with its key and value; an entry whose value is unknown makes the contents unknown.
- **Read**: where code reads data. A variable or `this` read through property reads is one read of that data, with what it holds, except the target an assignment replaces or the object of an element it replaces; an element read with a computed key, or a lookup by key, reads that element; a size read reads only the size; storing, appending and removing collection methods do not read their receiver; and a call to a project function reads what its summary says of its receiver and arguments. Reads in callbacks count.
- **Placeholder**: an element appended to a collection only to reserve its position: a constant appended right after a variable is given the collection's size, which names the element, then replaced by a store into the collection at a key that size flows to, through variables and the keys of a local container. Every way from the append must reach that store (through the container, every way reaches an entry under such a key, and a `for-of` over the container, neither breaking out nor leaving the function, reaches the store on every iteration), and nothing between them may read the element: no read of the collection as a whole or of data holding it, and no element read whose key has the size among its origins.
- **Unaddressed key**: an origin of a key a local map stores entries under that no keyed access to the map shares (a lookup or element read by key, a `has` check, a removal by key), while keyed accesses do reach entries stored under its other origins. Entries stored that way are only reached by going through the whole map, as in a list.
- **Fabrication**: what a branch of a decision makes up only so the code after it can treat the branch's result like the other branches': a placeholder appended in the branch that only the code after the decision replaces, or an unaddressed key whose origin is in the branch, under which the code after the decision stores entries.
- **Command**: something an arm runs for what it does rather than for a value: an expression statement whose value is discarded (a call, an update, an assignment to data other than a local of its function), or a returned call typed `void`. This is not purity: `const r = await save(x)` is not a command, and `list.push(x)` on a fresh local array is.
- **Control flow** of an arm: the `if`, `switch`, ternary, loop and `try` nodes written in it.
- **Decision**: a place choosing between arms on one value, each guarded by tests of its literal values. A branch's claim is **complete** when its conditions test only that value and do not overlap earlier arms; a trailing `else` or `default` is complete only when no `case` was unreadable and the value cannot be `null` or `undefined`. The **following** statement is the `return` after a run of `if`s or a `switch` without `default` whose arms all leave: it runs for the values no arm accepts, but is not an arm.
- **Site**: a written question about vocabularies (a condition, `case` labels, a typed list, or a complete table of the vocabulary to `true` and `false`), indexed per program by the literal values it mentions and the outcomes it leads to. Its **definition** is what names its group: the named function whose whole body it is, the declaration it initializes, or the `const` collection it tests membership of. An early-exit guard (an `if` without `else` whose branch ends in `return`, `throw`, `break` or `continue`) also leads, when false, to the statements after it in its list.

## Choices

- Types only: plain `string` values get no vocabulary guessed from the literals they are compared with.
- Every condition is read one way, as tests of a value with a claim.
- Sites compare outcomes as text, because the shared index is built without a checker.

## Limitations

- Returns are not followed through callbacks.
- A `throw` inside a `try` with a `catch` is not a rejection.
- A truthiness test of a `boolean` treats `false` as missing.
- A variable naming data is not updated when that data changes through another path.
- Writes in one expression count in order; only a branch of a conditional expression and the right side of a logical operator may not run. Merges do not follow labeled `break`s out of a `switch`, and a `case` clause with no statements reads the narrowing of the clause after it.
- Origins and reads compare keys by where they come from, not by value: an element read whose key comes from elsewhere is not a read of a placeholder, even if both keys could be equal.
- Calls are followed, for provenance, origins, effects and reads, to the implementation the checker resolves: an override in a subclass, or another implementation of an interface method, is not read. Library calls other than the collection methods above are computed. A parameter passed by a spread, or after one, gives existing data. A value held before a loop around a decision is existing data, whatever made it.
- Missing values are read through the checker's own narrowing, linked from its internal `getFlowTypeOfReferenceEx` and asked at flow nodes the model builds for each arm's condition.
- Values declared only in declaration files, such as `JSON` or `process.env`, count as code, not data.

Facts are pinned by the `model-facts` probe fixtures; see [native](../native.md#shared-decision-model).
