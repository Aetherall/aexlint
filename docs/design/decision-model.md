# Decision model

`native/model/` reads what code knows about values, once, from types and syntax. Typed rules are queries over it. Code knows **facts**: a test establishes one, it holds for a while, and code uses it. The rules find facts that are lost and rebuilt, established twice, established outside their owner, or spread across files.

## Glossary

- **Value**: data reached from a root (a variable, `this`, or an expression evaluated once) through property reads and literal-key element reads. Identity comes from symbols, not text; two calls written alike are different values. A variable that only names data is that data: after `const { kind } = item`, `kind` is `item.kind`.
- **Field**: the property declarations a value ends at. Two values are the same field when they share a name and a declaration.
- **Form**: a structural comparison key for an expression relative to a value: the value becomes `$`, literals compare by value, and external references by resolved symbol. The **syntactic form**, for shared indexes built without a checker, has a root node become `$` and other identifiers compare by name; it can miss a value reached through another variable naming it.
- **Vocabulary**: the finite literal values of a declared type, at least two string or number literals once `null` and `undefined` are removed.
- **Claim**: what a test establishes: the value is one of a set, within its vocabulary or among present, `undefined`, `null` and other falsy values. Claims compare as sets: same, opposite, or implies.
- **Test**: a place where code learns a claim: a literal comparison, `includes` or `has` on a collection of known values (a literal list, a literal tuple type, or a `new Set` of a literal list, directly or as a `const` initializer, read as declared), or a presence test (a truthiness test or a comparison with `null`/`undefined`). A value read through a default, `value ?? D` with `D` one of the literal values of its declared type, is tested, and switched on, as `value` itself: a claim about literal values ranges over those values alone, where the two read alike.
- **Rejection**: a place that rejects input without the model reading its claim: a `throw` under conditions reading input, including that of an earlier `if` in the same statement list that returns early on one side, or a call to a function that makes one. Narrowing-only tests are not rejections: they establish only what TypeScript's narrowed type keeps (presence, `typeof`, `instanceof`, `in`, type guards), including through a const boolean local, and a truthiness test beside a test requiring the same value to be an object. In rule messages this is a "check".
- **Guard** and **entry test**: a guard is a test after which code works only where the claim holds and otherwise leaves without using the value. An entry test is a function's guard on a parameter before its work; its **fallback** is the constant it leaves with.
- **Leaves**: cannot reach its end, by its ending: it returns, throws, breaks, continues or calls a function returning `never` on every way through it.
- **Callers**: the calls to a function across the program's project files, known only for a named function that compares a parameter with a string literal or declares a string result. A call to a member of a type the function's class instances are assignable to, such as an interface, counts as a call to the method. They are complete when the function is used only by being called: not passed, stored, default-exported, renamed on import or export, destructured or overloaded, and not a member a base class also declares. Calls on `any`, through element access and from outside the program are not seen.
- **Boundary**: where a value passes between functions: an argument to a parameter, a call's result, a store into a class's state, or a **gate** (a selector and handler in one object or class taking the same first parameter type). The questions there are what is known on the way in, whether the receiving type keeps it, and whether the receiver rejects it again.
- **Flow**: what a function does with its input: the data each value is built from, the rejections it makes, the calls it passes data to, and what it returns. A call is **discarded** when nothing receives its result: awaited or not, it is a whole expression statement.
- **Owner**: who a type belongs to: its class, a runtime value merged with it, or its declaring module or namespace. Importing a type does not transfer ownership. A property's owner is the named class, interface or type alias declaring it; code inside it is, for a class property, code of a class that has the property, otherwise code inside that owner. Ambient declarations and types in script files have no owner.
- **Predicate**: a parameterless member whose whole body is a field test of `this`. A **helper predicate** is an exported one-parameter function doing the same for its parameter. A **selector** is a function whose result is a boolean of tests on its parameters, or a type predicate.
- **Outcome**: what an arm produces: whether it runs **commands**, and what its result depends on: none, empty, constant, the value, parts of it, other data, or a mix. A constant result without commands is a **lookup**.
- **Optional settings**: for a function with one project object result type whose every return is an object literal or another value of one object type assignable to it, whether each returned object sets each optional property (marked `?` or typed with `undefined`): set, left out (missing or `undefined`), or maybe set (a value that may be `undefined`, or a spread that may carry it). A value other than a literal is read by its type: a required property is set, an optional one maybe set, a missing one left out.
- **Write**: a place where code changes data: an **assignment** (with `=`, each target of a destructuring assignment, or the variable of a for-in or for-of loop that does not declare it), an **update** (a compound assignment, `++` or `--`), or a **mutation**, a method called on a value. Assignments and updates **rebind** their target. A mutation is not known to change anything; each reader decides whether to count it.
- **Ending**: how a statement can end: by reaching its end, by a `break` leaving a statement around it, by a `continue` resuming a loop around it, by a `return`, or by a `throw` or a call returning `never`, each with the writes made on the way and the definitions reaching it. A loop ends when its condition fails or through a `break`; one without a condition, or whose condition is `true`, only through a `break`. A `switch` reaches its end when no case matches unless it has a `default` or covers every value. A `throw` in a `try` block goes to its `catch` clause, and a `finally` block runs on every way out. Without a checker, as for the shared index, no call is known to return `never` and no `switch` to cover every value.
- **Left values**: for an `if` or `switch` statement or a conditional expression run as a statement, the data its branches rebind on ways that reach its end and the statements after it read before every way rebinds it again, and the data they rebind before a `break` that the statements after the left statement read. Data counts when its root is a variable or parameter of the function declared outside the decision, or `this`; writes into one root are one entry. Writes in callbacks, in loops inside the decision, and mutations are not read. Nothing is left to statements starting with a `return`.
- **Definition**: what gives a place (a variable or `this`, then a property path) its value where code reaches a point: an assignment, update or destructuring that rebinds it, the declaration initializing its variable, or the value it held **before** the code being read. Each way out of a statement carries the definitions reaching it per place: a rebinding replaces the earlier ones, unless it may not run (in a branch of a conditional expression or on the right of `&&`, `||` or `??`); ways that join keep the definitions of both; a loop's ways also keep those of earlier iterations, and a `catch` those of any part of its `try` block.
- **Merge**: where the ways through a decision (an `if` or `switch` statement, or a conditional expression run as a statement) that reach its end rejoin. Each **arm** is one way in: the `then` or `else` branch, the `case` clause a way enters (falling through later clauses to the end or a `break` leaving the `switch`), a branch of the conditional expression, or the way no branch takes, when there is no `else` or the `switch` has no `default` and does not cover every value. An arm **finds a value missing** when the checker's narrowing says it is `undefined` or `null` there: for an arm entered by a condition, the type the value holds before the decision, read as its constraint when generic and with `undefined` and `null` added, narrowed by that condition alone, so an entry of a record whose type omits `undefined` is missing in `if (!entry)`; for a `case` clause, the type the checker narrows where it starts. Any test the checker narrows by counts: truthiness, comparisons with values typed `undefined` or `null`, `typeof`, `instanceof`, type guards and discriminants. A **phi** is a value at the merge: the definitions reaching it along each arm. It is **carried** when its value outlives the pass: data of `this`, or a variable declared outside the innermost loop around the decision; its arms then change state rather than choose what this pass works on. The value held before is read through the statements before the decision in each statement list around it, back to the declaration of its variable, but not past a loop or the start of the function.
- **Provenance**: the kinds of value an expression gives: **existing** data (a variable, parameter, property, element, `this`, or an entry a global collection's `get`, `at`, `find` or `findLast` returns), a **fresh** object (an object or array literal, `new`, a function, class or regular expression), a **constant** (an expression whose type is a single value: a literal, an enum member, `null`, `undefined`, a unique symbol), the **size** of a global collection or a string (`length`, `size`), or a **computed** value (any other operator, or a call not followed). Freshness is read from the expression, since no type states it. A `const` gives what its initializer gives, another variable or a parameter what its definitions reaching the read give; a call to a project function, or a read through a project getter, gives what its returns give, a parameter giving what the call's argument gives, and reaching the end of the body gives `undefined`; a generator, or an async function not awaited, gives a new object; a global collection method building a new array (`map`, `filter`, `slice`, `concat`, …), or a default library function building a new object (`JSON.parse`, `structuredClone`, `Array.from`, `Object.fromEntries`, …), gives a new object; a call back into a function being followed is computed; a conditional expression and `&&`, `||`, `??` give what either side gives. Provenance is read where the value is used: a new object the code before that point makes reachable from data that outlives it (an effect that may carry it into `this` or into data of a variable declared outside the code read) is existing data there, and so is the size of a collection read before an element is appended to it, which then names that element. A collection member is one every declaration of which belongs to a global type (`Array`, `ReadonlyArray`, `String`, `Map`, `ReadonlyMap`, `WeakMap`, `Set`, `ReadonlySet`, `WeakSet`), resolved in the global scope and compared by declaration, so a subclass inherits it and a project type of the same name is not one; on a union receiver, every member's type must agree on what it does.
- **Effect**: what a write does to the object it acts on (its **receiver**): **store** a value under a key (`Map.set`, `WeakMap.set`, an element assignment with a computed key), **append** one (`push`, `unshift`, `Set.add`), **remove** entries (`delete`, `clear`, `pop`, `shift`, `splice`), or **change** it otherwise (an array reordered or filled, an assignment or update of data inside it, or a method whose body is unknown run as a command). An effect also names the expressions whose data it may put into its receiver: the stored value, or every argument of a method whose body is unknown. Rebinding a variable is a definition, not an effect. The callbacks a global collection method runs during the call (`forEach`, `map`, `filter`, `sort`, …), the executor a `Promise` construction runs at once, and the callbacks `replace`, `replaceAll`, `JSON.parse`, `JSON.stringify` and `Array.from` call during the call, make their effects where they are written, and an effect on the element such a callback is given, or on the value a `for-of` loop over a collection binds, never rebound, acts on that element of the collection, written with the path segment `[]`, as in `rows.[]`, and one on the accumulator `reduce` gives its callback acts on the initial value given to `reduce`; their unseen code runs there too. A call or construction resolving to a project function with a body, or an assignment through a project setter with a body, makes the effects of its **summary**: the effects its body makes, including through the calls it makes, on its receiver (`this`) and its parameters (the summary also lists what it reads of them, see Read; which of them **escape**, given to unseen code directly, through a followed call letting them escape, yielded, carried into data that is neither local nor given, or referenced by a function it declares; and whether it is **opaque**: it may run unseen code, see Overwritten store, uses a variable of another function other than a `const` primitive, as a **closure** whose summary cannot name what that variable holds, or changes data other than its locals, receiver and parameters; and whether it **throws**, its body ending by a throw, directly, through a project function it calls that throws, or through a callback a global collection method runs during the call, outside a `try` block a `catch` handles), each with a property path and the parameters whose data it may carry, mapped at the call onto what the call is made on (`this` for `super`) and its arguments up to the first spread. Effects on the function's own locals, on module state, on a parameter it rebinds, and a construction's effects on the new object are not in it; a function reached again while it is summarized gives nothing on that call. Otherwise a call acts on its receiver only when every declaration of its callee is a method: a function held by a property or exported by a namespace, a callee the checker cannot resolve, and a default-library method outside the collection effects above have none, except the default library functions acting on an argument (`Object.assign`, `Object.defineProperty`, `Object.defineProperties`, `Object.setPrototypeOf`, and `Reflect.set`, `Reflect.defineProperty`, `Reflect.deleteProperty`, `Reflect.setPrototypeOf`), which change or remove from that argument and may carry the others into it.
- **Origin**: where a value comes from when the model cannot follow it further: a new object, a constant, a size read, a computed value, `this`, or a parameter or variable whose definitions are not seen. A property read, other than a size read or an accessor's, comes from that property of what its object comes from, so `media.id` read twice from one `media` is one origin. Origins are followed like provenance, through `const` initializers, the definitions of other variables reaching the read, conditional and logical operators, and calls to project functions (a parameter giving the origins of the call's argument), and through the entries of local containers: a lookup gives the origins of the values stored, and a `for-of` loop binds its keys and values to theirs. Unlike provenance, origins keep identity: two keys from different size reads are different origins. An element of data whose contents are not seen, read by element access or a lookup, bound by a `for-of` loop over it, or given to the callback of an array or set method on it, comes from that data's **elements**, one origin shared by every such read.
- **Contents**: what a local container holds: a variable of its function, never rebound, created empty (an empty array or object literal, or a global collection constructed without arguments) and used only as a container (the receiver of collection methods, by element access, for its size, iterated by `for-of`, or given to `Object.entries`, `Object.keys` or `Object.values`). Every effect in the function storing or appending into it is an **entry**, with its key and value; an entry whose value is unknown makes the contents unknown.
- **Read**: where code reads data. A variable or `this` read through property reads is one read of that data, with what it holds, except the target an assignment replaces or the object of an element it replaces; an element read with a computed key, or a lookup by key, reads that element; a size read reads only the size; storing, appending and removing collection methods do not read their receiver; a call to a project function reads what its summary says of its receiver and arguments, and a read through a project getter, or an assignment through a project setter, what the accessor's summary says of its object. A read a global collection method's callback makes of the element it is given, or a loop's body of the value it binds, reads that element of the collection, `[]` matching any element when data is compared. Reads in callbacks count.
- **Overwritten store**: a store into data nothing reads: an assignment of a declared property, other than through a setter, a store into a collection under a key, or an append right after a variable is given the collection's size, which names its position (a **placeholder**). It is replaced on every way from it, by at least one **fill**, a field by an assignment of the same field, an element by a store under a key every origin of the store's key flows to (through variables and the keys of a local container, as for a placeholder iterated back out of a map), and nothing between them can read it: no read of the data as a whole or of data holding it, of the field, or of an element whose key shares an origin. Unless the data is **private**, or local (see Local data), no **unseen** code runs between them, and no call to a project function that throws, which would leave the stored value to the caller's `catch`. Private data is a variable of the function, never rebound, initialized with a new object: by a construction that does not let the new object escape, or by a call that is not opaque. It is not referenced in the functions the function declares, other than callbacks a global collection method runs during the call, which count as the function's own code. Until the replacing store, it is only **contained**: read through to a primitive, written into, or read through to data itself only contained; the receiver of a project method that lets no receiver escape and is not a closure, or of a default library method whose result is a primitive or unused; returned; or passed to a project function that neither lets that argument escape nor carries it, or to a default library call that carries it nowhere, runs no function value given to it and whose result is a primitive or unused. Unseen code is an `await`, a `for await` loop or a `yield`, which let other code run, an iteration (by `for-of`, a spread or an array destructuring) of a value whose `[Symbol.iterator]` no global collection or typed array type declares, other than a default library method's result on a known one or a followed call, a read, destructuring included, or write through an accessor that is neither a project one whose summary is not opaque nor declared by the default library, a call that is neither to a project function with a body nor declared by the default library, a default library call given a function value written elsewhere, or running one through `call`, `apply` or `bind`, unless it names a project function that is not opaque and makes no effect, or a function of the default library such as `Number`, or a call to an opaque project function. Constructing a project class without a constructor, or calling `super` from one, runs the field initializers up to the first class with a constructor: it is unseen only when they run unseen code, when that constructor is opaque, or when the first base outside the project is not from the default library.
- **Local data**: data only the function's own variables can reach. A local variable is one of the function, rebound or not, whose every definition gives a new object (a literal, a library result such as `map`'s, a construction whose constructor lets no receiver escape, or the result of a project function returning only its own local data, which its summary calls **fresh**) or an entry of a local container holding only local data, and whose every reference is contained (as for private data), rebinds it, or stores it into such a container. The variables a `for-of` loop over such a container binds are read alike, and such a container is local itself, since it is only used as a container and what comes out of it is local. References in callbacks a global collection method runs during the call count as the function's own. Variables and containers vouch for each other, as the greatest set meeting these terms. Code outside the function cannot reach local data, even when the function throws.
- **Lost write**: an overwritten store that is lost whole. It sets a declared property, not through a setter, an element of an array or tuple, or an entry of a local container (see Contents) its function only reads by key. A placeholder still grows its collection, and a store into another map, set or object may still fix where its key comes in iteration order, so neither is lost whole.
- **Unaddressed key**: an origin of a key a local map stores entries under that no keyed access to the map shares (a lookup or element read by key, a `has` check, a removal by key), while keyed accesses do reach entries stored under its other origins. A map is a global `Map`, a `Set`, whose values are its keys, or an object created empty and used only by element access. Entries stored that way are only reached by going through the whole map, as in a list.
- **Buffer**: a local container (see Contents) that only defers its entries to one `for-of` loop over it, or one `forEach` call on it or on its `entries`, `keys` or `values`, its **drain**: every entry is put in before the drain, which runs once per container and is its only read as a whole; before it, the function only looks entries up, checks or removes them by key, never reads its size, prepends (`unshift`), reorders or clears it, and nothing touches it once the drain starts but the drain, on the entry it is given. An entry, by the origins of its key, is **settled** when only the drain reaches what it stores once stored: no lookup, check or removal shares an origin with its key (an append, no element read by key at all); every way from the store reaches the drain, so no `return`, `throw`, `try` or call to a project function that throws can drop it; the stored value is a primitive, or a variable not referenced between the store and the drain, nor before the store in a loop that runs again unless declared in it, nor in a closure, nor before the store other than as private allows, holding a new object or a constant as defined together with the key (a value defined after the key's definition, on every way from it, pairs with it), or else nothing changes other data and no unseen code runs between the store and the drain; and, in a map, set or object, no other entry may replace it: its store runs once per container, or its key is new each time (a new object, or a size read followed on every way by an append to that collection, a **reserved position**). Handing a settled entry over where it is stored would give the drain the same value. Its **ordered** reads and effects are those between the store and the drain that the deferral keeps on one side of the drain: a read of data the drain changes, or an effect on data the drain reads or changes, unless both act on one collection under different literal keys, or any effect on data that outlives the function (neither private nor local) when the drain may throw, which would stop that code early. It is **exposed** to the unseen code (see Overwritten store) on one side, between the store and the drain or in the drain, while the other side reads or changes data such code may reach: anything but the buffer, private or local data, a function or class declaration, a primitive an expression gives, a primitive variable of the function no closure uses, and, in the drain, the entry it is given when its value is new or a primitive. An `await` is unseen code like any other: another task may run there.
- **Backing**: the check a non-null assertion of a container's entry relies on, which the checker cannot connect to it. The assertion is on an element read or lookup (a literal index, `at` with a literal, the size minus a literal, a map's `get`, or an object's entry by a key that is not an integer literal) whose type includes `undefined` or `null` while the type of the entries it holds does not, and is not `any`, `unknown` or `never`. The check holds the container larger than that position, or holding the key (`has`, `in`, `Object.hasOwn` or `hasOwnProperty` with the same value), where the assertion runs. It reads a size as a truthiness test or compared with an integer literal, through negations, `&&`, `||` and the function's variables, `const` or never rebound, holding a size or a check. It is either a **guard**, earlier in a statement list around the assertion, whose branch leaves when the check fails, which calls an assertion function declared `asserts condition` with it, or which calls a project function whose summary **guarantees** it, or the condition of a branch holding the assertion. A function guarantees a check of a container given to it when a guard at the top of its body throws when the check fails, an assertion call there makes it hold, or a project function it calls there guarantees it, and it removes no entries from that container. The check may be outside a callback that a global collection method calls with its elements. Nothing between them, counting loops and callbacks around the assertion in full, removes entries, changes the container through a method with an unknown body, or rebinds it.
- **Filter**: a guard in a `for-of` body, or in the callback of a `forEach` call, that skips elements by a test on the element alone: an `if` without `else` whose branch only continues the loop, or only returns nothing from the callback, after statements that only declare variables, never rebound, from initializers making no effect, with a test making no effect; neither calls a project function that throws, which hoisting would make throw before earlier elements' work. Every read the test and those initializers make is of data the loop does not change: no effect in the loop acts on it or on data holding it, and nothing in the loop rebinds it, so an element reached twice is tested alike. It is **exposed** to the unseen code on one side, the test and its declarations or the rest of the loop, while the other side reads or changes data such code may reach, as for buffers.
- **Default**: where code decides what an absent optional property stands for: a `??` or `??=` reading the property, or a default in an object binding pattern destructuring it, with a constant of the property's type without `undefined` and `null`. The property is declared by an owner (see Owner), every declaration belonging to it, and the default is **inside** when written inside that owner. Defaults of one property are compared across the program by declaration and by the property's type where it is read, so the instantiations of a generic property are apart.
- **Scan**: a loop emitting values computed from state it carries from one pass to the next. The state is a variable of the function, declared before the loop, that the loop rebinds outside its iteration control (a `for` statement's initializer and incrementor, or the variable a `for-of` or `for-in` loop assigns) and reads other than where a statement writes it. An emit is an append or store (see Effect) into data declared outside the loop whose value or key reads such a variable, directly or through a constant of the pass initialized from one. Its other work is the effects on other data declared outside the loop, and the variables it rebinds but only reads where a statement writes them. The state an emit reads, directly or through such a constant, is what its values are **computed** from; the rest only decides when values come. A **pass counter** is state the loop writes once, by `++` or `+= 1`, in a statement of its body itself, where the write runs whenever that statement does, with no `continue` of the loop before it; a counter that is also decremented, or advanced by other steps, is not one. Callbacks the loop declares are not read for emits.
- **Derivation**: a value computed from one property of data outside the property's owner (see Owner): a call whose only argument reads the property, which holds instance data (a property signature, or a property declaration or getter that is not static, whose type has no call signatures), by a callee computing from its arguments alone (a function, or a static method or one of an object literal, not a method of an instance, which would also read the instance's data). The call makes no effect, the body of a project callee makes no effect on data declared outside it (effects of the calls it makes count as their summaries list them), and the result is used and is not a boolean, which a test would establish. Derivations by the same callee declaration from the same property declaration are compared across the program; their **readers** are the functions they are written in. Calls with more arguments, and methods on the property's value, are not derivations.
- **Own key**: a key given to a method of the value stored under it. The map is local (see Contents) and every entry stores, under a key, a new object made in the function, or the value read back from the map, as in get-or-create. In a `for-of` loop over its entries binding `[key, value]`, or a `forEach((value, key) => …)`, a project method on the value is given the key. A value stored under several keys, or not made by the function, is not one: its key is not its own.
- **Fabrication**: what a branch of a decision writes for the code after it that is never used as written: an overwritten store made in the branch that only the code after the decision replaces, a lost write or a placeholder, or an unaddressed key whose origin is in the branch, under which the code after the decision stores entries.
- **Command**: something an arm runs for what it does rather than for a value: an expression statement whose value is discarded (a call, an update, an assignment to data other than a local of its function), or a returned call typed `void`. This is not purity: `const r = await save(x)` is not a command, and `list.push(x)` on a fresh local array is.
- **Control flow** of an arm: the `if`, `switch`, ternary, loop and `try` nodes written in it.
- **Decision**: a place choosing between arms on one value, each guarded by tests of its literal values. A branch's claim is **complete** when its conditions test only that value and do not overlap earlier arms; a trailing `else` or `default` is complete only when no `case` was unreadable and the value cannot be `null` or `undefined`. The **following** statement is the `return` after a run of `if`s or a `switch` without `default` whose arms all leave: it runs for the values no arm accepts, but is not an arm.
- **Site**: a written question about vocabularies (a condition, `case` labels, a typed list, or a complete table of the vocabulary to `true` and `false`), indexed per program by the literal values it mentions and the outcomes it leads to. Its **definition** is what names its group: the named function whose whole body it is, the declaration it initializes, or the `const` collection it tests membership of. An early-exit guard (an `if` without `else` whose branch ends in `return`, `throw`, `break` or `continue`) also leads, when false, to the statements after it in its list.

## Choices

- Types only: plain `string` values get no vocabulary guessed from the literals they are compared with.
- Every condition is read one way, as tests of a value with a claim.
- Sites compare outcomes as text, because the shared index is built without a checker.
- Code the model does not see may reach any data that is neither private nor local, including data handed to it earlier: no reading of one function can rule that out, and reentrancy through listeners is common. So the model narrows what such code reaches only through what it can know locally: data never handed out (private and local data), and what each function lets escape, guarantees or may throw, from its summary. Facts that claim a flaw require nothing exposed; advice built on them may rely on the rest, saying so.

## Limitations

- Returns are not followed through callbacks.
- A `throw` inside a `try` with a `catch` is not a rejection.
- A truthiness test of a `boolean` treats `false` as missing.
- A variable naming data is not updated when that data changes through another path.
- Writes in one expression count in order; only a branch of a conditional expression and the right side of a logical operator may not run. Merges do not follow labeled `break`s out of a `switch`, and a `case` clause with no statements reads the narrowing of the clause after it.
- Origins and reads compare keys by where they come from, not by value: an element read whose key comes from elsewhere is not a read of a placeholder, even if both keys could be equal. Buffers do too when they settle an entry, but not when they order it: two keys are only known to differ as different literals.
- A settled entry's value is read as an object, not through the data it references. Private and local data are read the same way: data stored into them from outside stays reachable through them, which the model does not follow.
- Calls are followed, for provenance, origins, effects and reads, to the implementation the checker resolves; another implementation of an interface method is not read. For effects, reads and unseen code, a method or accessor a project subclass overrides is not followed, unless named through `super`: its call may run the override, so it counts as code the model does not see. Library calls other than the collection methods above are computed. A parameter passed by a spread, or after one, gives existing data. A value held before a loop around a decision is existing data, whatever made it.
- Missing values are read through the checker's own narrowing, linked from its internal `getFlowTypeOfReferenceEx` and asked at flow nodes the model builds for each arm's condition.
- Values declared only in declaration files, such as `JSON` or `process.env`, count as code, not data.
- Code the model does not see may read or change any data it may reach. For data that is not private, that includes data handed to it earlier, which no local reading can rule out. Private data never escapes, so only what is given to such code now can reach it, as summaries' escapes tell.
- A property declared without accessors is taken as plain, even when an implementation stores it through a setter.
- Calls to the default library are taken not to throw, and code the model does not see counts as unseen code rather than as throwing.
- Defaults are compared by their constant, so a fallback that only displays absence, such as `"-"`, counts like any other.
- Backings, filters, own keys, scans and buffers are read within one function, along with the callbacks a global collection method runs during its call. Called functions count for backings only through what their summaries guarantee.

Facts are pinned by the `model-facts` probe fixtures; see [native](../native.md#shared-decision-model).
